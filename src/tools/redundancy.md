# 🧯 Redundancy

**What this is:** how many of a thing to own — a spare where failure is costly, one where replacement is trivial.

## ⚖️ The rule

<!-- begin table -->
| Signal | Keep |
| --- | --- |
| Failure is costly or slow to undo (phone, boot drive) | a spare |
| Durable and trivially replaced (fork, mug) | exactly one |
| Wear item with a clear replacement signal | one, replaced on wear |
<!-- end table -->

## 📱 Spares

- **Two phones** — one street device, one secure; either can cover the other.
- **Two boot drives** — Linux and Windows recovery media.
- **Cold copies** — off the machine, per the backup flow in [../code/backup.md](../code/backup.md).

## 🍴 Singles

Simple, durable items earn no spare: one fork, one mug, one plate. A second copy is clutter, not resilience.

## 🔁 Replacement over spares

Buy once, replace on wear. The "Own?" and "Replacement signal" columns in the domain notes are the trigger to replace, not to stockpile.
